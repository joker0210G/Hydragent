# 🌙 Hydragent Dreaming Phase

The Dreaming Phase is Hydragent's cleanup and learning engine. It turns messy desk activity into durable library knowledge, keeps `USER.md` and `SOUL.md` healthy, links related pages with Graphify-style edges, and extracts reusable skills from successful work.

This is not a generic maintenance job. It is part of Hydragent's identity path:

- the desk holds the active work
- draft paper holds temporary in-flight chat
- pages hold condensed knowledge
- books group related pages
- shelves group related books
- Graphify connects the library

---

## 1. Why Dreaming Exists

Hydragent gets better when it does not keep raw chat forever.

The Dreaming Phase does four jobs:

1. compress temporary draft paper work into pages
2. update the user's long-term memory files
3. connect pages, books, and shelves into a graph
4. review successful work and extract reusable skills

That keeps the system fast, searchable, and aligned with the Hydragent memory model.

---

## 2. What Triggers Dreaming

Dreaming can run when any of these happen:

- the active work area goes idle
- enough new draft material has accumulated
- memory files are near their size limit
- a cleanup command is requested
- the system wants to review recent work for skill extraction

The trigger does not need a heavy mode switch. It only needs a clear boundary where the system is safe to compact and summarize.

---

## 3. The Hydragent Dreaming Cycle

```text
1. Capture
   -> read draft paper, recent work, and current memory notes

2. Compress
   -> summarize important chat into pages
   -> preserve facts, decisions, preferences, and tasks

3. Link
   -> connect pages to books and shelves
   -> add Graphify-style edges for related ideas

4. Trim
   -> update or prune USER.md and SOUL.md if they exceed limits
   -> remove low-value repetition, not useful identity

5. Review
   -> inspect recent successful tool paths
   -> promote stable patterns into reusable skills
```

Each step keeps Hydragent's library useful instead of letting the raw transcript become the product.

---

## 4. Step 1: Capture

Dreaming starts by reading the right material, not everything.

It should gather:

- active desk context
- temporary draft paper
- recent pages and books
- recent graph links
- current `USER.md` and `SOUL.md` content

It should not blindly hoard every line of chat. The point is to choose the material worth keeping.

---

## 5. Step 2: Compress Into Pages

Hydragent should turn the useful parts of recent work into pages.

A page should usually contain:

- a title or theme
- the main fact or decision
- any stable user preference
- any reusable workflow clue
- any important cross-reference to another page or book

Good pages are short enough to reuse and specific enough to matter.

The goal is to make the memory layer read like a library, not a log dump.

---

## 6. Step 3: Link Pages, Books, and Shelves

After pages are written, Graphify-style linking connects them.

Hydragent should:

- attach a page to one or more books when it fits more than one topic
- attach a book to one or more shelves when it belongs to multiple categories
- connect related pages with edges
- keep related topics reachable through the graph

This is what makes the memory useful during later work. Hydragent can move from one idea to its neighbors instead of searching raw chat again.

---

## 7. Step 4: Trim USER.md and SOUL.md

Hydragent keeps two important human-facing memory files:

- `USER.md` for preferences, habits, and durable facts
- `SOUL.md` for the system's persistent identity and tone

The dreaming phase should keep them within their limits and prevent them from becoming bloated.

Rules:

- preserve facts that still matter
- compress repeated detail into one clearer note
- delete stale or contradictory memory when it is no longer useful
- keep identity intact even while trimming size

Do not treat trimming as deletion of the user. It is only cleanup of the memory text.

---

## 8. Step 5: Review and Skill Coaching

Dreaming also looks for reusable work patterns.

If Hydragent just completed a reliable multi-step path, it should ask:

- did the pattern solve a real repeated problem?
- is the pattern stable enough to reuse?
- does the pattern deserve to become a skill?

If yes, Hydragent can extract a reusable skill and keep it as part of the skill engine.

This is where the system learns from its own good behavior instead of only reacting to mistakes.

---

## 9. Budget Modes

Hydragent should let dreaming run at different cost levels.

### Balanced Mode

- use the model for summaries and fact extraction
- use Graphify locally for linking and clustering
- good default for most users

### Turbo Budget Mode

- minimize or avoid model calls during dreaming
- rely on local graph building and rule-based cleanup
- good when cost matters more than summary quality

### Super Scholar Mode

- use the strongest available model for summarization and consolidation
- use Graphify for local structure building
- good when memory quality matters most

### Custom Mode

- let the user choose which parts use a model
- let the user choose which parts stay local
- keep the same output shape regardless of cost profile

The mode changes how Dreaming works, not what Hydragent is.

---

## 10. Output of Dreaming

After one successful dreaming cycle, Hydragent should have:

- new or updated pages
- updated books and shelves
- stronger graph links
- smaller and cleaner `USER.md` and `SOUL.md`
- optional new reusable skills
- a cleaner active workspace for the next round of work

That is the whole point: turn messy temporary work into a structured Hydragent library.

---

## 11. What Dreaming Must Not Do

Hydragent should not let dreaming become another pile of uncontrolled logs.

It should not:

- overwrite useful identity details
- erase important pages just to make files shorter
- lose graph links when summarizing
- flatten distinct books into one noisy note
- hide useful changes inside generic cleanup text

Dreaming is allowed to simplify. It is not allowed to forget the core of Hydragent.

---

## 12. Summary

The Dreaming Phase is Hydragent's memory metabolism.

It captures the useful parts of the desk, compresses them into pages, groups them into books and shelves, links them with Graphify, trims memory files when needed, and promotes repeated success into reusable skills.

That keeps Hydragent fast, organized, and still unmistakably Hydragent.
